# Getting help

Start with the [documentation](https://docs.unset.sh/) and the affected repository's README. The
[organisation map](https://github.com/unset-sh/.github/blob/main/MAP.md) identifies which repository owns each part
of unset.sh. A repository's own support instructions take precedence over this default.

## Ask a question or report a problem

Search the affected repository's open and closed issues first. If the answer is missing, use its **Issues → New issue**
chooser to ask a usage question, report a bug, suggest a change or describe an accessibility barrier. Include the
repository or package, version or commit, what you tried, and the result. Keep reproduction steps small and remove
secrets and personal information from logs and screenshots.

If you cannot identify the owner or its issue tracker is unavailable, open a
[question in the organisation repository](https://github.com/unset-sh/.github/issues/new/choose) and name the component.
Maintainers can direct it to the right place. Public support does not have a guaranteed response time.

## Private or sensitive reports

- For a suspected vulnerability, follow [Security reporting](https://github.com/unset-sh/.github/blob/main/SECURITY.md).
- For harassment or other conduct concerns, use the reporting route in our
  [Code of conduct](https://github.com/unset-sh/.github/blob/main/CODE_OF_CONDUCT.md).

For proposed code or recipe contributions, read the
[contribution policy](https://github.com/unset-sh/.github/blob/main/CONTRIBUTING.md) before opening a pull request.
